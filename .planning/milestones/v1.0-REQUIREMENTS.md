# Requirements Archive: v1.0 — Projection / Read-Model Subsystem

**Archived:** 2026-06-24
**Status:** All 31 v1 requirements satisfied (verified by milestone audit)

## v1 Requirements

### Projector Lifecycle

- [x] **PROJ-01**: A developer can define a projector via a DSL (`use Orkestra.Projector`) that maps event types to read-model updates — Phase 3
- [x] **PROJ-02**: A projector consumes events asynchronously via an EventStore catch-up subscription — Phase 1
- [x] **PROJ-03**: A projector persists its last-processed position and resumes from it after a restart — Phase 2
- [x] **PROJ-04**: A projector processes events strictly in order — Phase 2
- [x] **PROJ-05**: Projectors are supervised and isolated — one projector halting or crashing does not stop the others — Phase 3

### Storage Abstraction & PostgreSQL Adapter

- [x] **STORE-01**: A storage-adapter behaviour defines the contract (write, reset) so backends are pluggable — Phase 1
- [x] **STORE-02**: A PostgreSQL/Ecto storage adapter persists read-model updates — Phase 2
- [x] **STORE-03**: The checkpoint update and the read-model write commit atomically in a single Ecto transaction — Phase 2
- [x] **STORE-04**: A projection's storage is isolated in its own Ecto.Repo with a dedicated connection pool — Phase 2

### Migrations (per-projection, isolated)

- [x] **MIG-01**: Each projection owns its tables and an isolated migration history — Phase 2
- [x] **MIG-02**: A developer can migrate a single projection (`mix orkestra.projection.migrate <name>`) — Phase 3
- [x] **MIG-03**: A developer can roll back a single projection's migrations independently — Phase 3
- [x] **MIG-04**: A developer can drop a single projection's tables and checkpoint without affecting other projections — Phase 3

### Rebuild / Replay

- [x] **RBLD-01**: A developer can rebuild a projection from scratch — reset, replay, transition to live — Phase 3
- [x] **RBLD-02**: Rebuild is gap-free and uses batched writes suitable for large event streams — Phase 3

### Error Handling

- [x] **ERR-01**: On a projection error, the event is retried with backoff, configurable per projector — Phase 1
- [x] **ERR-02**: When retries are exhausted, the failing event is parked to a dead-letter store — Phase 1
- [x] **ERR-03**: After parking, the projector halts, preserving read-model integrity — Phase 1
- [x] **ERR-04**: A halted projector's status is persisted and observable — Phase 2

### Reads / Queries

- [x] **READ-01**: A developer can query a read model directly with Ecto — Phase 2
- [x] **READ-02**: An optional generated `Queries` module exposes generic helpers per read model — Phase 5

### Telemetry & Observability

- [x] **TEL-01**: Each processed event emits an OpenTelemetry span — Phase 4
- [x] **TEL-02**: Projection lag is exposed as a positional metric — Phase 4
- [x] **TEL-03**: Rebuild progress is exposed as a separate metric — Phase 4
- [x] **TEL-04**: Projector errors and halts emit telemetry events/counters — Phase 4

### MCP Integration

- [x] **MCP-01**: The MCP server provides a `gen_projection` generator — Phase 5
- [x] **MCP-02**: The MCP server provides a `gen_read_model` generator — Phase 5
- [x] **MCP-03**: Projections surfaced in MCP introspection resources — Phase 5

### Configuration

- [x] **CFG-01**: The `:ultimus` app-key bug is fixed (→ `:orkestra`) — Phase 3
- [x] **CFG-02**: Per-projection repo/storage configuration has a clean config story — Phase 3
- [x] **CFG-03**: New storage dependencies declared as optional deps — Phase 3
