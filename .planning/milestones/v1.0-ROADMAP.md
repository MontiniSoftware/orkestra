## Overview

Complete projection / read-model subsystem for Orkestra — from correctness foundations through the Projector GenServer, Ecto adapter, developer-facing DSL, operational tooling, telemetry, and MCP code generators. Postgres/Ecto adapter built first as the reference implementation; shared lifecycle abstraction ready for future MongoDB and Elasticsearch adapters.

## Milestone Summary

**Key Decisions:**

- EventStore catch-up subscription (not MessageBus) as the consumption model for projectors
- Checkpoint + read-model write in one Ecto.Multi transaction — non-negotiable correctness constraint
- Per-projection isolated Ecto.Repo with separate `migration_source` for independent lifecycle
- Storage.write/4 returns `ops :: term()` — adapter-agnostic write descriptor
- subscribe_from_position/3 uses exclusive `> from_position` semantics matching Spear
- InMemory Agent.get_and_update atomically registers subscriber + snapshots history (no race/gap)
- Checkpoint and DeadLetter wrapped in Code.ensure_loaded? guard — library compiles without Ecto
- Oban migration pattern: Orkestra owns DDL, consumer controls timing and Repo
- event_data field uses :map (JSON/jsonb) — avoids unsafe atom deserialization

**Tech Debt Incurred:**

- 4 mix task Postgres integration tests have known migration_lock race failures
- @moduledoc slug example shows word-boundary splitting inconsistency (cosmetic)
- Lag metric is always 0 during normal live processing (definitional in sequential GenServer); meaningful only for halted projectors
- gen_queries Queries module uses runtime repo injection — matches codebase convention but differs from compile-time capture
