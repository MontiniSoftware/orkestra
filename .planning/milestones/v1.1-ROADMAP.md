## Overview

Added an ES/OpenSearch storage adapter to the existing projection subsystem. Developers can define ES projections that consume domain events and maintain searchable read models in Elasticsearch or OpenSearch — with zero-downtime rebuild, batch indexing, and an Elixir query DSL.

## Milestone Summary

**Key Decisions:**
- Snap ~> 0.16 as the ES client (only maintained Elixir ES client)
- ES-first, Postgres-second checkpoint ordering for at-least-once semantics
- `dynamic: strict` enforced on all managed indexes
- write/4 returns pure descriptor maps; GenServer owns HTTP execution
- Snap.Indexes.hotswap/5 for zero-downtime rebuilds
- GenServer registered by name for rebuild pause/resume

**Issues Resolved:**
- GenServer.whereis(module) integration gap — fixed by adding :name to child_spec
- gen_es_projection missing document_id/1 — added to scaffold
- Snap.Auth.ApiKey for ES API key auth (Snap only ships Basic Auth)

**Issues Deferred:**
- AWS SigV4 auth (AUTH-01) — future milestone
- Rebuild crash recovery (RRES-01) — future milestone
- Search/count/get_by_id helpers (QHLP-01) — future milestone

**Technical Debt Incurred:**
- Phases 7 and 9 need PostgreSQL for full test execution (verified statically)
- Snap.Document.index arity comments inconsistent (/6 vs /4)
- GenServer discards cluster/index from init/1 return (only extracts engine)
