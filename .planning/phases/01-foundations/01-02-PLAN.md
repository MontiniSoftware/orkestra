## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `subscribe_from_position/3` | A `subscriber` pid is supplied by the caller; the adapter pushes events to it. In v1 callers are trusted internal code (the Phase 2 Projector GenServer), not external input |
| EventStoreDB gRPC → EventStoreDB adapter | Event payloads arrive over Spear; `data`/`metadata` originate from the event store |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-02 | Elevation of Privilege | `subscribe_from_position/3` subscriber pid | accept | Only trusted internal callers pass the pid; no external input reaches this arg in v1 (RESEARCH.md Security Domain). Revisit if a public subscription API is added |
| T-01-03 | Tampering | Out-of-order / gapped push delivery (InMemory) | mitigate | Subscriber registration + history snapshot and live push happen inside a single `Agent.get_and_update` so concurrent appends cannot reorder or drop messages (RESEARCH.md Pitfall 3); enforced by the in-order/gap-free test assertions |
| T-01-04 | Information Disclosure | event `data`/`metadata` forwarded to subscriber | accept | Events delivered only to the explicitly-subscribed pid; no broadcast to unintended processes; low-value library-internal data path |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs in this plan; `spear` is an already-present optional dep verified in mix.lock. No `[ASSUMED]`/`[SUS]` packages — no install checkpoint needed |

Honest note: this plan defines contracts and a test-only in-memory adapter plus a compile-only EventStoreDB path; there is no auth/session/network-input surface owned by this phase. The one real control is the in-order/atomic push discipline.
