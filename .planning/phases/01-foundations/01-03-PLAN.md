<objective>
Create the two Orkestra-owned Ecto schemas — `Orkestra.Projection.Checkpoint` (persisting the integer position and the halt status, per D-02/ERR-03) and `Orkestra.Projection.DeadLetter` (parked-event fields per ERR-02) — plus `Orkestra.Projection.Migration` that creates and drops the `projection_checkpoints` and `projection_dead_letters` tables (Oban-style library-owned migration). All three modules are wrapped in `Code.ensure_loaded?` guards so the library still compiles when ecto is absent.

Purpose: ERR-02 (a failing event is parked with projector, position, event, error, attempts, timestamp) and ERR-03's persisted side (a halted status that survives the GenServer so the halt is observable, not a silent stall). These are the data structures; the runtime that writes them is Phase 2.
Output: `checkpoint.ex`, `dead_letter.ex`, `migration.ex`, and a schema-fields test.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | `DeadLetter.event_data` deserialization | mitigate | `event_data` is typed `:map` and persisted as jsonb/JSON (Jason-encodable), not `:erlang.binary_to_term` — there is no unsafe-atom deserialization surface (RESEARCH.md Security Domain; mirrors the Snapshot module's `:safe` posture by avoiding term deserialization entirely) |
| T-01-06 | Information Disclosure | parked event payloads in `projection_dead_letters` | accept | Stored in the consumer's own Postgres under their access control; Orkestra owns only the schema/table shape, not row-level access. Low risk for v1; documented for the operator |
| T-01-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager installs in this plan; `ecto`/`ecto_sql` were declared (optional, OK verdict) in Plan 01-01. No `[ASSUMED]`/`[SUS]` packages — no install checkpoint needed |

Honest note: this plan defines schema/table shapes and a migration. There is no runtime write path, no auth, and no network surface owned by this phase — the writers come in Phase 2. The one substantive control is using JSON (not term deserialization) for `event_data`.
