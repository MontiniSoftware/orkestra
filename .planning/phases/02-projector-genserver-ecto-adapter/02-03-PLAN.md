<objective>
Implement `Orkestra.Projector.GenServer` — the runtime that processes events
end-to-end. On start it defers a checkpoint load (so `Sandbox.allow` can run in
tests), reads the persisted position, and — unless halted — subscribes from
`last_position` with exclusive `>` semantics (PROJ-03). It applies pushed events
strictly sequentially via `handle_info`, the OTP mailbox guaranteeing in-order,
single-consumer processing (PROJ-04). Each event commits the read-model write
(from the injected storage adapter's Multi) and the checkpoint upsert in one
`Ecto.Multi` transaction (STORE-03). On failure it retries with `Lifecycle`
backoff via `Process.send_after`; on exhaustion it writes the dead_letter row and
`halted=true` in one transaction and stays alive idle (ERR-04). The read model is
a plain Ecto schema on the per-projection Repo, queryable directly (READ-01).

The binding proof is the simulated-crash-between-writes + restart test asserting
no double/missed write — the non-negotiable atomic-commit invariant.

Purpose: Deliver the projection subsystem's runtime with the atomic co-write and
visible-halt guarantees that the whole milestone rests on.
Output: lib/orkestra/projector/gen_server.ex + its :postgres-tagged integration test.
</objective>

| EventStore push → GenServer mailbox | Events arrive as process messages; the only untrusted-shaped input crossing into the projector |
| GenServer → per-projection Repo | The atomic transaction boundary; checkpoint + read-model co-write |
