**Common pattern across all three tasks:**
1. Module naming follows Mix convention: `Mix.Tasks.Orkestra.Projection.Migrate` maps to `mix orkestra.projection.migrate`
2. `use Mix.Task`
3. `@impl Mix.Task` on `run/1`
4. Call `Mix.Task.run("app.config")` first to ensure config is loaded (RESEARCH Pitfall 1: modules must be loaded before `Module.concat/1`)
5. Resolve projector module: `module = Module.concat([projector_module_str])` -- more forgiving than `String.to_existing_atom` per RESEARCH Pitfall 1
6. Call `config = module.__projection_config__()` to get repo, projector_name, migrations_path, migration_source
7. Use `Ecto.Migrator.with_repo/3` -- NEVER call `repo.start_link/1` directly (RESEARCH Anti-Patterns)
8. Handle `run([])` with `Mix.raise/1` for missing argument
9. Include `@shortdoc` and `@moduledoc` with usage example

**`lib/mix/tasks/orkestra.projection.migrate.ex`** (MIG-02):
```elixir
if Code.ensure_loaded?(Ecto.Migrator) do
  defmodule Mix.Tasks.Orkestra.Projection.Migrate do
    @shortdoc "Run migrations for a single Orkestra projection"
    @moduledoc """
    Runs all pending migrations for the named projection.

    The projection's migration directory and migration tracking table are
    discovered via `__projection_config__/0` on the projector module
    (generated by `use Orkestra.Projector`).

    ## Usage

        mix orkestra.projection.migrate MyApp.OrderProjector
    """

    use Mix.Task

    @impl Mix.Task
    def run([projector_module_str | _rest]) do
      Mix.Task.run("app.config")
      module = Module.concat([projector_module_str])
      config = module.__projection_config__()

      {:ok, _, _} =
        Ecto.Migrator.with_repo(config.repo, fn repo ->
          Ecto.Migrator.run(repo, config.migrations_path, :up,
            all: true,
            migration_source: config.migration_source
          )
        end)

      Mix.shell().info("Migrations complete for #{config.projector_name}")
    end

    def run([]) do
      Mix.raise("mix orkestra.projection.migrate requires a projector module name\n\n" <>
        "Usage: mix orkestra.projection.migrate MyApp.OrderProjector")
    end
  end
end
```

IMPORTANT: The `migration_source` option. Per RESEARCH Assumption A1, `Ecto.Migrator.run/4` may or may not accept `migration_source` as an option directly. The safer approach is to ensure the Repo's Application config includes `migration_source`. However, `Ecto.Migrator.run/4` in ecto_sql 3.12 DOES accept `migration_source:` in the opts keyword list (this is passed through to `Ecto.Migration.SchemaMigration` via `SchemaMigration.ensure_schema_migrations_table!/3`). Use the opts approach -- it's more explicit and doesn't require the consumer to configure `migration_source` in their Repo config (the DSL generates it).

Create `lib/mix/tasks/orkestra.projection.rebuild.ex` implementing the five-step rebuild sequence per D-11 and D-12.

Wrapped in `if Code.ensure_loaded?(Ecto.Migrator) do ... end`.

The rebuild task is the most complex mix task. Per D-11, the sequence is:
1. Stop the projector GenServer via `Supervisor.terminate_child/2`
2. Roll back all projection migrations
3. Re-migrate
4. Reset checkpoint (delete checkpoint + dead_letter rows)
5. Restart the GenServer via `Supervisor.restart_child/2`

Per D-12, live transition after rebuild is natural -- the restarted GenServer subscribes from position -1 (no checkpoint exists) and catches up through the full event stream, then goes live automatically. No special transition code needed.

```elixir
if Code.ensure_loaded?(Ecto.Migrator) do
  defmodule Mix.Tasks.Orkestra.Projection.Rebuild do
    @shortdoc "Rebuild an Orkestra projection from scratch"
    @moduledoc """
    Rebuilds a projection by stopping its GenServer, rolling back and
    re-running all migrations, resetting the checkpoint, and restarting
    the GenServer. The projector then replays the full event stream from
    position 0, transitioning to live automatically once caught up.

    Requires the projector to be running under `Orkestra.Projection.Supervisor`.
    If the projector uses a custom supervision tree, stop and restart it manually.

    ## Usage

        mix orkestra.projection.rebuild MyApp.OrderProjector

    ## Options

    - `--yes` - Skip confirmation prompt (for scripting/CI).
    - `--supervisor` - Supervisor name (default: `Orkestra.Projection.Supervisor`).
    """

    use Mix.Task

    import Ecto.Query, only: [from: 2]

    alias Orkestra.Projection.{Checkpoint, DeadLetter}

    @impl Mix.Task
    def run(args) do
      {opts, positional, _} =
        OptionParser.parse(args, strict: [yes: :boolean, supervisor: :string])

      case positional do
        [projector_module_str | _] ->
          unless Keyword.get(opts, :yes, false) do
            Mix.shell().info(
              "This will DROP and RECREATE all tables for #{projector_module_str}."
            )

            unless Mix.shell().yes?("Continue?") do
              Mix.raise("Rebuild cancelled.")
            end
          end

          Mix.Task.run("app.start")

          module = Module.concat([projector_module_str])
          config = module.__projection_config__()

          supervisor_name =
            case Keyword.get(opts, :supervisor) do
              nil -> Orkestra.Projection.Supervisor
              name -> String.to_existing_atom("Elixir.#{name}")
            end

          # Step 1: Stop the projector GenServer
          Mix.shell().info("Stopping #{config.projector_name}...")

          case Supervisor.terminate_child(supervisor_name, module) do
            :ok -> :ok
            {:error, :not_found} ->
              Mix.raise(
                "Projector #{config.projector_name} not found under #{inspect(supervisor_name)}. " <>
                "Ensure it is started under Orkestra.Projection.Supervisor."
              )
          end

          # Step 2: Roll back all migrations
          Mix.shell().info("Rolling back migrations...")

          {:ok, _, _} =
            Ecto.Migrator.with_repo(config.repo, fn repo ->
              Ecto.Migrator.run(repo, config.migrations_path, :down,
                all: true,
                migration_source: config.migration_source
              )
            end)

          # Step 3: Re-migrate
          Mix.shell().info("Re-running migrations...")

          {:ok, _, _} =
            Ecto.Migrator.with_repo(config.repo, fn repo ->
              Ecto.Migrator.run(repo, config.migrations_path, :up,
                all: true,
                migration_source: config.migration_source
              )
            end)

          # Step 4: Reset checkpoint and dead letters
          Mix.shell().info("Resetting checkpoint...")

          {:ok, _, _} =
            Ecto.Migrator.with_repo(config.repo, fn repo ->
              repo.delete_all(
                from(c in Checkpoint, where: c.projector_name == ^config.projector_name)
              )
              repo.delete_all(
                from(d in DeadLetter, where: d.projector_name == ^config.projector_name)
              )
            end)

          # Step 5: Restart the GenServer -- subscribes from -1, replays all events
          Mix.shell().info("Restarting #{config.projector_name}...")

          case Supervisor.restart_child(supervisor_name, module) do
            {:ok, _pid} ->
              Mix.shell().info(
                "Rebuild complete. #{config.projector_name} is replaying from position 0."
              )
            {:error, reason} ->
              Mix.raise(
                "Failed to restart #{config.projector_name}: #{inspect(reason)}"
              )
          end

        [] ->
          Mix.raise(
            "mix orkestra.projection.rebuild requires a projector module name\n\n" <>
            "Usage: mix orkestra.projection.rebuild MyApp.OrderProjector"
          )
      end
    end
  end
end
```

Key implementation notes:
- Uses `Mix.Task.run("app.start")` (not just `app.config`) because the rebuild task needs running processes (supervisor, GenServer). `app.start` ensures the full application is booted.
- Confirmation prompt by default (Claude's Discretion -- safety for destructive operation). Skip with `--yes`.
- Configurable supervisor name via `--supervisor` flag (Claude's Discretion, addressing RESEARCH Pitfall 4).
- Step 4 dead_letter query uses `d.projector_name` (bound to DeadLetter) — matches the `from(d in DeadLetter, ...)` binding.
- RBLD-02 (gap-free rebuild) is naturally satisfied: the GenServer starts from position -1 with no checkpoint, catches up through all events sequentially in the same path as normal startup. No special rebuild path.

**Test cases:**

Note: Testing Mix tasks that call `Ecto.Migrator.with_repo/3` from within a Sandbox transaction is tricky because `with_repo` starts a new Repo connection. For proper integration testing, use `Ecto.Adapters.SQL.Sandbox.mode(ProjectionRepo, {:shared, self()})` in setup -- this shares the connection across processes.

Actually, the fundamental issue is that `Ecto.Migrator.with_repo/3` tries to start the Repo process, which is already running from test_helper. This will fail. The Migrator detects the Repo is already started and uses it directly (ecto_sql handles this). So the tests should work as long as the Repo is in shared mode.

BUT: Migrations run DDL statements that cannot be rolled back inside a sandbox transaction. This means:

1. Tests that run `migrate` create real tables that persist
2. Tests that run `rollback`/`drop` drop those tables
3. Tests must run in order and clean up after themselves

The practical approach: Use `setup_all` for the one-time migration setup. Individual tests call the mix tasks directly and verify the outcomes. Use a unique projector name per test. Clean up in `on_exit`.

REVISED APPROACH: Keep tests simple. Rather than fighting Sandbox + DDL semantics, test each task individually with explicit cleanup:

1. `test "migrate creates tables"` -- run migrate, verify table exists, then run rollback as cleanup
2. `test "rollback removes last migration"` -- run migrate, then rollback, verify table is gone
3. `test "drop rolls back all and deletes checkpoint/dead_letter"` -- insert a checkpoint row, run migrate, run drop, verify table gone AND checkpoint deleted
4. Rebuild cannot be integration-tested without a running supervisor + GenServer + event store, which is heavy. Test the task structure compiles and the error paths (missing module, missing supervisor).
