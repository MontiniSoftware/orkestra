Add a new public function `projector_span_attrs/3` to `lib/orkestra/telemetry.ex`, placed immediately after the existing `event_attrs/1` function (after line 51, before the `metadata_attrs` functions). Follow the exact pattern of `command_attrs/1` and `event_attrs/1`.

The function takes plain values (not structs) because the projector GenServer deals with raw event maps from EventStore, not EventEnvelope structs:

```elixir
@doc "Creates span attributes for a projector event-processing span."
@spec projector_span_attrs(String.t(), map(), non_neg_integer()) :: map()
def projector_span_attrs(projector_name, event, position) do
  %{
    "orkestra.projector.name"     => projector_name,
    "orkestra.projector.position" => position,
    "orkestra.event.type"         => event.type,
    "orkestra.event.id"           => event[:id] || ""
  }
end
```

Key constraints:
- No new module aliases needed
- Use `event[:id]` (bracket access, not dot) because the event is a plain map, not a struct -- the `:id` key may not exist
- Use `event.type` (dot access) because `.type` is always present on events from the EventStore
- Place BEFORE the `metadata_attrs` functions to keep attribute helpers grouped together

```elixir
defp apply_event(event, state) do
  %{
    repo: repo,
    projector_name: projector_name,
    storage_adapter: storage_adapter,
    adapter_opts: adapter_opts
  } = state

  position = event.global_position

  Tracer.with_span "orkestra.projector.apply_event",
    attributes: OTel.projector_span_attrs(projector_name, event, position) do

    case storage_adapter.write(projector_name, event, position, adapter_opts) do
      {:ok, read_model_multi} ->
        # ... existing checkpoint Multi construction (unchanged) ...
        # ... existing repo.transaction(combined) ...

        case repo.transaction(combined) do
          {:ok, _changes} ->
            Logger.debug(...)  # existing log line

            # TEL-02: Emit lag metric after successful commit
            lag = (state.last_seen_position || position) - position
            :telemetry.execute(
              [:orkestra, :projector, :lag],
              %{lag: lag},
              %{projector_name: projector_name}
            )

            # TEL-03: Emit rebuild progress if in rebuild mode
            new_state =
              if state.rebuild_total && state.rebuild_total > 0 do
                replayed = state.rebuild_events_replayed + 1

                :telemetry.execute(
                  [:orkestra, :projector, :rebuild_progress],
                  %{events_replayed: replayed, total_events: state.rebuild_total},
                  %{
                    projector_name: projector_name,
                    percent: Float.round(replayed / state.rebuild_total * 100, 1)
                  }
                )

                %{state | attempts: 0, rebuild_events_replayed: replayed}
              else
                %{state | attempts: 0}
              end

            {:noreply, new_state}

          {:error, step, reason, _changes} ->
            # TEL-01: Set span error status on transaction failure
            Tracer.set_status(:error, inspect(reason))

            Logger.warning(...)  # existing log line
            handle_failure(event, {step, reason}, state)
        end

      {:error, reason} ->
        # TEL-01: Set span error status on adapter failure
        Tracer.set_status(:error, inspect(reason))

        Logger.warning(...)  # existing log line
        handle_failure(event, reason, state)
    end
  end
end
```

CRITICAL: Keep ALL existing Logger calls, checkpoint Multi construction, and control flow exactly as-is. Only add the span wrapping, the Tracer.set_status calls on error branches, and the :telemetry.execute calls on the success branch.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GenServer internal state -> span attributes | Span attributes are derived from internal GenServer state fields (projector_name, event.type, position) -- no external/untrusted input crosses this boundary |
| GenServer state -> :telemetry measurements | Telemetry measurements (lag, attempts, delay_ms) are numeric values derived from internal counters -- no external input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | OTel span attributes | mitigate | Span attributes include only event.type, event.id, projector.name, and position -- no event payload data (event.data is never included in span attributes) |
| T-04-02 | Tampering | projector_name in telemetry metadata | accept | projector_name is a compile-time constant from inspect(__MODULE__) in the DSL macro -- not user-controlled input; no injection risk |
| T-04-03 | Denial of Service | :telemetry.execute frequency | accept | :telemetry.execute is synchronous and lightweight; one call per event processed is proportional to workload; no amplification vector |
