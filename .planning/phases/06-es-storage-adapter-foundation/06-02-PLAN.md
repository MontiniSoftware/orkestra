<!-- Postgres adapter write/4 pattern (lib/orkestra/projection/storage/postgres.ex): -->
def write(projector_name, event, position, opts) do
  handler = Keyword.fetch!(opts, :handler)
  case handler.(projector_name, event, position) do
    {:ok, multi} when is_struct(multi, Ecto.Multi) -> {:ok, multi}
    {:error, reason} -> {:error, reason}
  end
end

<!-- Postgres adapter reset/2 pattern: -->
def reset(projector_name, opts) do
  repo = Keyword.fetch!(opts, :repo)
  schema = Keyword.fetch!(opts, :schema)
  repo.delete_all(from(s in schema, where: s.projector_name == ^projector_name))
  :ok
end

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Adapter -> Snap.Cluster -> ES cluster | HTTP requests cross network boundary to ES/OpenSearch |
| User-supplied index_mapping/0 -> Snap.Indexes.create | User-defined mapping body sent to ES index creation API |
| Application config -> Snap.Auth | Credentials flow from config to HTTP Authorization header |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Tampering | ensure_index | mitigate | Always inject `dynamic: strict` into mappings block regardless of user input; prevents mapping explosion from unmapped fields |
| T-06-04 | Information Disclosure | reset/2 (_delete_by_query) | accept | reset/2 only called during rebuild (privileged operation); documents clearing is intentional; no PII exposure risk beyond normal ES access |
| T-06-05 | Denial of Service | detect_engine GET / | mitigate | On connection failure, default to :elasticsearch and log warning; do not crash the projector supervision tree |
| T-06-06 | Spoofing | index name derivation | accept | Index name derived from projector module slug (compile-time controlled, not user input); no injection vector |
| T-06-07 | Information Disclosure | Snap.Cluster config | mitigate | Document in moduledoc: use runtime config + secrets manager for credentials; never commit to git; production must use https:// |
</threat_model>
