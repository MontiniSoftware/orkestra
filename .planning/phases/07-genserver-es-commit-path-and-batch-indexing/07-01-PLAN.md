Extend `Orkestra.Projector.GenServer` to execute ES write operations from Phase 6's descriptor maps: single-document `index` calls in live mode via `Snap.Document.index/6`, and batched bulk indexing during catch-up/rebuild via `Snap.Bulk.perform/4`. Add per-item partial failure detection for bulk responses, OTel spans for every ES operation, and telemetry metrics for batch throughput.

Purpose: The ES storage adapter (Phase 6) is purely functional -- it returns descriptor maps. The GenServer must own all ES I/O and branching logic (live vs catch-up mode) to fulfill BULK-01, BULK-02, BULK-03, OBSV-01, OBSV-02.

Output: Modified `gen_server.ex` with complete ES commit path + modified `telemetry.ex` with ES span helper.

    Receives `(event, %{action: :index, id: id, doc: doc}, position, state)`. Builds a `%Snap.Bulk.Action.Index{id: id, doc: doc}` struct. Branches on `state.es_mode`:

    - `:live` -- call `commit_es_single_doc/4`
    - `:catching_up` -- append `{position, action_struct}` to `state.es_buffer`. If `length(new_buffer) >= state.es_batch_size`, call `flush_es_buffer/3`. Otherwise return `{:noreply, %{state | es_buffer: new_buffer}}`.

    **New private function: `commit_es_single_doc/4`**

    Receives `(event, action_struct, position, state)`. Extracts `cluster`, `index`, `engine` from `state.adapter_opts` (using `Keyword.fetch!` for cluster/index, `Keyword.get(adapter_opts, :engine, :elasticsearch)` for engine).

    Wraps the `Snap.Document.index(cluster, index, action_struct.doc, action_struct.id)` call in an OTel span:
    ```
    Tracer.with_span "orkestra.es.single_doc_index",
      attributes: Map.put(OTel.es_span_attrs(projector_name, index, engine), "orkestra.projector.position", position) do
    ```

    On `{:ok, _}`: call `commit_es_checkpoint/3` to update Postgres checkpoint, then emit `[:orkestra, :projector, :lag]` telemetry and optionally `[:orkestra, :projector, :rebuild_progress]` if `rebuild_total` is set. Reset attempts to 0. Return `{:noreply, updated_state}`.

    On `{:error, reason}`: call `Tracer.set_status(:error, inspect(reason))`, log warning with `orkestra: :projector` tag, call `handle_failure(event, reason, state)`.

    **New private function: `flush_es_buffer/3`**

    Receives `(last_event, buffer, state)`. Extracts `cluster`, `index`, `engine` from `state.adapter_opts`. Converts buffer to actions: `Enum.map(buffer, fn {_pos, action} -> action end)`. Gets `{last_position, _} = List.last(buffer)`.

    Records `started_at = System.monotonic_time(:millisecond)`.

    Wraps `Snap.Bulk.perform(actions, cluster, index, page_size: length(actions), page_wait: 0)` in an OTel span:
    ```
    Tracer.with_span "orkestra.es.bulk_flush",
      attributes: OTel.es_span_attrs(projector_name, index, engine, length(actions)) do
    ```

    CRITICAL: Always pass `page_size: length(actions), page_wait: 0` to avoid 15-second default page_wait.

    On `:ok`: compute `elapsed_ms`, emit `[:orkestra, :projector, :es_bulk_flush]` telemetry with measurements `%{batch_size: length(actions), duration_ms: elapsed_ms}` and metadata `%{projector_name: projector_name, index: index, engine: engine}`. Call `commit_es_checkpoint/3` with `last_position`. If `rebuild_total` is set, update `rebuild_events_replayed` by adding the buffer length and emit `[:orkestra, :projector, :rebuild_progress]`. Clear buffer in state, reset attempts. Return `{:noreply, updated_state}`.

    On `{:error, %Snap.BulkError{errors: errors} = bulk_err}`: Log warning with error count and structured per-item errors (map each to `%{type: e.type, message: e.message, status: e.status}`). Call `Tracer.set_status(:error, inspect(bulk_err))`. Call `handle_failure(last_event, bulk_err, %{state | es_buffer: []})`. Do NOT advance checkpoint.

    On `{:error, reason}` (connection/HTTP error): same pattern -- `Tracer.set_status(:error, ...)`, log, `handle_failure`.

    **New private function: `commit_es_checkpoint/3`**

    Receives `(last_event, position, state)`. Builds a standalone `checkpoint_multi` using the existing pattern (lines 236-248 in current gen_server.ex) with `Ecto.Multi.new() |> Ecto.Multi.insert(:checkpoint, ...)`. Calls `state.repo.transaction(checkpoint_multi)` directly -- NOT `Ecto.Multi.append`. On `{:ok, _}`, log debug. On `{:error, step, reason, _}`, log warning and call `handle_failure`.

    **New private function: `update_es_checkpoint_only/3`**

    Receives `(event, position, state)`. For `:skip` events -- no ES write needed, just advance checkpoint. Calls `commit_es_checkpoint/3`, then emits lag telemetry. Same success/failure pattern as `commit_es_single_doc` but without the Snap.Document call.

    **Extend `terminate/2`:**

    Add a new `terminate/2` clause BEFORE the catch-all that handles ES buffer flush on shutdown:
    ```
    def terminate(reason, %{es_buffer: [_ | _]} = state) do
      # Best-effort flush of remaining buffered ES operations before shutdown
      flush_es_buffer_on_terminate(state)
      # Still unsubscribe if needed
      terminate(reason, %{state | es_buffer: []})
    end
    ```

    The `flush_es_buffer_on_terminate/1` helper performs a synchronous `Snap.Bulk.perform` call without OTel spans (process is terminating). On success, update the checkpoint. On failure, log warning -- data will be replayed on restart (at-least-once semantics).

    **Anti-patterns to avoid (from RESEARCH.md):**
    - Do NOT use `Ecto.Multi.append` for ES writes -- ES path uses `repo.transaction(checkpoint_multi)` standalone
    - Do NOT compare `storage_adapter == Orkestra.Projection.Storage.Elasticsearch` -- branch on the shape of `write/4` return (`%{action: :index}` vs Ecto.Multi)
    - Do NOT advance checkpoint on `%Snap.BulkError{}` -- call `handle_failure/3`
    - Match `{:error, %Snap.BulkError{errors: errors}}` explicitly -- not `{:error, %{errors: errors}}`
    - Do NOT log `adapter_opts` or cluster credentials in structured logs
    - Always use `page_size: length(actions), page_wait: 0` for bounded buffer flush

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GenServer -> Snap (HTTP) | ES write operations cross network boundary; response data is untrusted |
| Event handler -> GenServer | Handler return value shapes the document; validated by `dynamic:strict` index mapping (Phase 6) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | flush_es_buffer | mitigate | Match `{:error, %Snap.BulkError{}}` explicitly and call handle_failure; do NOT advance checkpoint on partial failures |
| T-07-02 | Denial of Service | apply_es_event (catching_up) | mitigate | es_batch_size cap (default 500) enforced; buffer length checked on every append; configurable via startup config |
| T-07-03 | Information Disclosure | Logger.warning in ES paths | mitigate | Log projector_name and position only; never log adapter_opts (contains cluster module which may expose connection URL); never log document content |
| T-07-04 | Tampering | commit_es_checkpoint | accept | Standalone Postgres checkpoint transaction (not appended to ES result). At-least-once semantics: crash between ES write and checkpoint update causes replay on restart, which is safe because ES writes are idempotent (deterministic _id + full index upsert) |
| T-07-05 | Denial of Service | Snap.Bulk.perform page_wait | mitigate | Always pass `page_wait: 0` and `page_size: length(actions)` for bounded GenServer buffers to prevent 15-second default hang |
</threat_model>
