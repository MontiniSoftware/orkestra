<objective>
Extend the `Orkestra.Projector` macro DSL to support `backend: :elasticsearch` with a `project_es/2` macro, and wire `storage_adapter.init/1` in the GenServer so ES projectors perform engine detection and index creation at startup.

Purpose: Enable developers to define ES projectors using the same macro DSL pattern as Postgres projectors, with the generated `child_spec/1` automatically wiring the ES storage adapter, cluster, index, and handler function -- without any changes to existing Postgres projectors.

Output: Modified `projector.ex` with ES macro support, modified `gen_server.ex` with `:init_adapter` handler, new ES DSL test file.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Compile-time macro → Runtime GenServer | Handler functions accumulated at compile-time are injected into runtime dispatch; `Macro.escape/1` prevents AST injection |
| GenServer → ES adapter init | `storage_adapter.init/1` performs HTTP I/O (engine detection, index creation); failure must stop the GenServer cleanly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `project_es/2` macro | mitigate | Use `Macro.escape/1` on handler_fn before accumulation (same pattern as existing `project/2`) |
| T-08-02 | Information Disclosure | `handle_info(:init_adapter)` | mitigate | Logger.error logs only `projector_name` and `inspect(reason)`; never log `adapter_opts` (contains cluster config) |
| T-08-03 | Tampering | `index_mapping/0` user callback | accept | Already mitigated by `Storage.Elasticsearch.ensure_index` which forces `dynamic: "strict"` via `Map.put` (Phase 6, elasticsearch.ex:240) |
| T-08-04 | Denial of Service | `storage_adapter.init/1` failure | mitigate | GenServer returns `{:stop, {:adapter_init_failed, reason}, state}` on init failure; supervisor restart strategy handles recovery |
| T-08-05 | Tampering | Compile-time validation bypass | mitigate | `__before_compile__/1` raises `CompileError` if `backend: :elasticsearch` without `:cluster`/`:index` or if both `project/2` and `project_es/2` handlers exist in same module |
</threat_model>
